# مطعم الذواقة — المنيو الإلكتروني

موقع منيو مطاعم احترافي (داكن، RTL، متحرك) مع لوحة تحكم إدارة.

## المتطلبات

- Node.js 24 LTS

## التشغيل

```bash
npm install
npm run db:seed   # زرع بيانات مبدئية (4 أصناف / 19 طبق) — idempotent
npm run dev       # التطوير على http://localhost:3000
npm run build && npm run start   # الإنتاج
```

## مسارات الزبون

- `/` — صفحة الترحيب + زر «تفقّد الآن»
- `/menu` — شبكة أصناف **بطاقات مربعة** (عمودان بالضبط على الهاتف → 3 على الوسط → 4 على الشاشات الكبيرة)؛ الأصناف المخفية لا تظهر
- `/menu/<slug>` — منتجات الصنف (المخفي منها لا يظهر؛ و404 إذا كان الصنف نفسه مخفياً) + تخصيص المكوّنات (إزالة اختيارية / إضافة بسعر؛ المكوّن الإلزامي 🔒 لا يُزال) + السلة
- السلة: زر 🛒 في الترويسة → «تأكيد الطلب» يُرسل الطلب للوحة الادمن

## لوحة الادمن

- `/admin` — تسجيل الدخول (كلمة مرور واحدة من `.env`: `ADMIN_PASSWORD`) — واجهة فاتحة مريحة (مستقلة عن ثيم الزبون الداكن)
- `/admin/dashboard` — **إدارة الأصناف كاملة**: إضافة صنف (اسم + أيقونة + صورة اختيارية) + إخفاء/إظهار + تعديل الاسم + حذف (مع تنظيف صور الأطباق) + **ترتيب بالسحب (Drag & Drop)** مع زر «حفظ الترتيب»
- `/admin/categories/<slug>` — **لوحة إدارة الصنف** (تعديل الاسم، إخفاء/إظهار من المنيو، حذف، تغيير الصورة) + **لوحة الرؤية**: إخفاء المنتجات غير المتوفرة من منيو الزبون (تأكيد بالعدد، بلا حذف) وإظهارها لاحقاً + كل طبق بأقسام أكورديون متحركة: **معلومات الطبق** (مفتوح: الاسم، السعر، صورة اختيارية تُبقى الحالية عند تركها فارغة، الوصف، التوفّر) و**المكونات**/**الإضافات** (لكل طبق على حدة) و**خيارات أخرى** (حذف الطبق) — مع منع الإرسال المزدوج ورسالة «تم الحفظ ✓»
- `/admin/orders` — قائمة طلبات الزبائن مع الإجمالي والتاريخ والحذف

التعديلات تنعكس فوراً على صفحات الزبون.

## البيئة (`.env`)

| متغير | الوصف |
|---|---|
| `ADMIN_PASSWORD` | كلمة مرور الادمن |
| `SESSION_SECRET` | سر توقيع الجلسة (HMAC) |
| `CURRENCY` | رمز العملة (افتراضياً `دج` — دينار جزائري) |
| `TURSO_URL` | (اختياري محلياً، مطلوب في Vercel) رابط قاعدة Turso `libsql://...` — عند ضبطه تُستخدم القاعدة السحابية بدل الملف المحلي |
| `TURSO_TOKEN` | (اختياري محلياً، مطلوب في Vercel) رمز الوصول لقاعدة Turso |
| `BLOB_READ_WRITE_TOKEN` | (مطلوب في Vercel لرفع الصور) رمز مخزن Vercel Blob — يُربط تلقائياً عند إنشاء Storage → Blob |

## النشر (Vercel + Turso)

`node:sqlite` يعمل محلياً فقط؛ على Vercel تُستخدم قاعدة **Turso** (libSQL) تلقائياً عند ضبط المتغيرين:

1. أنشئ قاعدة في [Turso](https://turso.tech) وأصدر **Token** منها.
2. ارفع المستودع إلى GitHub.
3. في [vercel.com](https://vercel.com) → **Add New Project** → Import من GitHub.
4. أضف متغيرات البيئة: `TURSO_URL`, `TURSO_TOKEN`, `ADMIN_PASSWORD`, `SESSION_SECRET`.
5. لرفع الصور في الادمن: **Storage → Create Blob** (رابط الصور يُربط تلقائياً بـ `BLOB_READ_WRITE_TOKEN`).
6. **Deploy** — قاعدة Turso تُهيّأ تلقائياً عند أول تشغيل (schema idempotent).

كل دفعة `git push` إلى `main` تعيد النشر تلقائياً (auto-deploy).

محلياً: `npm run db:seed && npx tsx scripts/smoke.ts` تشغّل أيضاً ضد Turso عندما يكون `TURSO_URL` مضبوطاً.

## الاختبارات

```bash
npm run db:seed && npx tsx scripts/smoke.ts   # تحقق آلي: بيانات + CRUD + سلة + مصادقة
npm run lint
npm run build
```

التسجيل (غير حظري) في `logs/app.log`. قاعدة البيانات SQLite في `data/menu.db` (محلياً) أو Turso (عند ضبط `TURSO_URL`).
